# 0001 — UTF-8 표현 단위 비교

- 상태: `PLANNED`
- 작성일: 2026-10-05
- 분류: 공식 과제와 별도로 설계한 사전 독립 실험
- 연결 노트: [문자와 바이트](../../notes/0001-text-representation.md)
- 구현: 아직 없음
- 실행 결과: 아직 없음

## 질문과 예상

문자열을 코드 포인트(code point)와 UTF-8 바이트(byte)로 각각 셀 때 길이가 어떻게 달라지는가? 한글·이모지가 포함된 입력에서 두 길이가 달라질 것으로 예상하지만 아직 측정하지 않았습니다.

## 입력과 비교 조건

직접 만든 입력 `hello`, `안녕하세요`, `AI 공부`, `🙂`, `e\u0301`, 빈 문자열을 고정해 비교합니다. `e\u0301`은 문자 `e` 뒤에 결합 악센트 U+0301을 붙인 문자열을 뜻하며, 역슬래시 여섯 글자를 그대로 입력하지 않습니다. 원본 입력을 보존하고 정규화(normalization) 적용 여부를 명시합니다.

측정할 항목: 입력의 이스케이프 표현, 코드 포인트 수, UTF-8 바이트 수, 인코딩(encoding) 후 디코딩(decoding) 결과가 원본과 같은지. 바이트 길이를 모델 토큰 수라고 부르지 않습니다.

## 구현·실행 절차

1. `src/`에 작은 독립 구현을 직접 작성합니다.
2. ASCII, 한글, 결합 문자, 빈 입력에서 예상한 동작을 확인합니다.
3. 정확한 실행 명령, 언어·버전, 코드 커밋(commit)을 여기에 기록합니다.
4. [결과 양식](../../templates/result.md)을 복사해 `results/0001-utf8-representation/summary.md`에 측정값과 한계를 기록합니다.
5. 노트와 실험 목록을 갱신합니다. 재실행 여부는 별도로 표시합니다.

## 해석의 한계

작은 자체 입력을 비교하는 실험입니다. 학습된 토크나이저(tokenizer)의 품질, 압축률, 모델 성능을 평가하지 않습니다. 코드 포인트 수와 사용자가 인식하는 글자 수를 동일시하지 않습니다.
